# 靜態網頁規劃書:《新聞數字翻譯機》

> 日期:2026-10-19 · 狀態:規劃稿(未開始實作) · 層級自評:**合格**(點子有新聞依據、範圍可做完;還沒做使用者驗證,所以還不到「強」)

---

## 1. 作品簡介

**一句話:** 把新聞裡看不懂的大數字,翻譯成「你的月薪」「滷肉飯」「你那時幾歲」。

**白話故事:**
這個月的新聞到處是大數字:立法院在推的普發現金 2 萬元、基隆捷運 696.89 億、選舉候選人的財產申報。讀者看到「696 億」通常沒感覺,滑過去就忘了。

這個網頁每則新聞做成一張卡片。卡片上寫原始數字和新聞來源,底下有一個「翻譯」按鈕,可以換成三種生活尺度:

- **換成錢感**:等於每個台灣人出幾元、你要工作幾個月
- **換成東西**:等於幾碗滷肉飯、幾杯手搖飲(單價可以自己改)
- **換成時間**:這個工程完工那年你幾歲

**成品長這樣:** 一頁、手機可用,上方輸入「月薪」和「年齡」(不送出、不存伺服器),下方 5 到 8 張新聞卡片,每張可以單獨截圖分享。

**為什麼選這個:** 四個獨立發想方向(小孩視角、遊戲設計、零預算一小時、反向思考)**都各自想到「把數字換成生活單位」**,這是最強的收斂訊號。而且這個做法跟新聞題材無關,下個月有新新聞,只要改一個 JSON 檔。

## 3. 目標使用者與情境

- **主要:** 18 到 30 歲、會滑新聞但不會細讀的學生和年輕上班族
- **使用情境(JTBD):** 「當我在社群看到一則大數字新聞時,我想在 10 秒內知道這跟我有什麼關係,這樣我才能決定要不要在意、要不要轉傳。」
- **次要:** 想要現成換算圖卡的老師或社團

---

## 4. 功能範圍

### 這次要做(MVP)
1. 上方輸入:月薪(預設帶基本工資,**數字要查勞動部確認**)、年齡、滷肉飯單價(預設 40 元,可改)
2. 新聞卡片:標題、原始數字、狀態標籤(已通過/草案/預報)、來源連結
3. 每張卡片的三種翻譯:錢感、東西、時間
4. 「複製這張卡的文字」按鈕(比截圖功能簡單,先做這個)
5. 頁尾:換算公式全部公開、資料最後更新日期

### 刻意不做
- 不接即時 API(颱風預報會變,寫死的資料錯了會誤導人)→ 颱風卡只連到氣象署,不做換算
- 不做留言、登入、排行榜
- 不做「圖片下載」→ 等真的有人想分享再加
- 候選人資產**不做比大小、不排名**(理由見第 9 點)

## 6. 資料設計

只用一個 `news.json`,每則新聞一筆:

```json
{
  "id": "keelung-mrt",
  "title": "基隆捷運總經費核定",
  "amount": 69689000000,
  "unit": "TWD",
  "status": "已通過",
  "perCapita": true,
  "targetYear": 2033,
  "source": "https://...",
  "checkedAt": "2026-10-19"
}
```

- `perCapita`:要不要除以台灣人口(人口數也寫在 JSON 頂層,附內政部來源)
- `targetYear`:有填才顯示「那時你幾歲」
- `checkedAt`:每筆資料最後核對日,頁面上顯示出來

**換算公式(全部公開在頁尾):**
- 幾個月薪水 = 金額 ÷ 月薪
- 每人負擔 = 金額 ÷ 人口
- 幾碗 = 金額 ÷ 單價
- 那時幾歲 = 年齡 + (目標年 − 2026)

## 7. 技術與部署

- 純 HTML + CSS + 原生 JS,一個 `index.html`、一個 `news.json`,**不用框架**
- 部署:GitHub Pages
- 本機測試:`python -m http.server`(因為 `fetch` 讀 JSON 不能直接用 `file://` 開)
- 換算函式寫成獨立小函式,附一個 `test.html` 或 console assert 檢查 4 條公式

## 9. 假設與風險

### 最危險的假設
**「換算成生活單位,讀者就會有感。」** 如果同學看完覺得「所以呢」,整個作品就沒價值。
→ **最便宜的驗證:** 先不寫程式,用紙或一張圖做 2 張卡片,拿給 3 個人看,問「你會轉傳嗎?為什麼?」

### 其他風險
| 風險 | 處理方式 |
|---|---|
| 選舉期間政治中立 | 候選人資產只做「個人換算」,不排名、不並排比較;所有參選人用同一套規則,或乾脆這版先不放 |
| 資料錯誤或過時 | 每筆標 `checkedAt`;草案一律標「草案」;颱風不換算 |
| 換算本身誤導(例:總經費 ÷ 全國人口不等於每人真的要付) | 頁尾寫清楚「這是比喻尺度,不是實際負擔」 |
| 個資 | 月薪年齡只在瀏覽器計算,不存、不送出;頁面寫明 |
| 版權 | 只引用數字和標題,不貼新聞內文 |

## 附錄 A:點子池(發想過程)

用 adhd 方法開 4 個獨立方向,各自產生 5 個點子,共 20 個,依「底層做法」分組。分數:N=新穎、V=可行、F=切題(0 到 10)。

**A. 把數字換成生活單位**(4 個方向都想到 → 收斂成主案)
- 普發 2 萬元能換什麼 `[N5 V9 F9]`
- 候選人資產換算成「你要存幾年」`[N6 V8 F8]`
- 一餐花費對照荷莫茲油價/法國通膨/葉門糧援 `[N7 V6 F7]`
- 法國物價抗議 vs 台灣便當價的薪水滑桿 `[N6 V7 F6]`

**B. 時間軸/倒數**
- 基隆捷運 2033 時光膠囊:「通車那年你幾歲」`[N7 V9 F8]` → 已併入主案「換成時間」
- 颱風倒數 + 防颱待辦清單(localStorage 勾選)`[N4 V9 F7]`

**C. 遊戲化**
- ★ **台北市長辯論 Bingo**:10/31 辯論前做,格子是「又提捷運」「數字對不上」等,網址參數決定卡片,朋友傳同一連結就能一起玩 `[N8 V8 F8]`
- 普發 2 萬 60 秒分配速通 + 隨機事件卡 `[N7 V7 F7]`
- 貨船躲演習區小遊戲 `[N7 V6 F5]`
- 供應鏈事件卡 roguelike `[N8 V3 F6]`

**D. 跟我有什麼關係(查表)**
- 選縣市,顯示今天哪些新聞跟你有關 `[N6 V7 F7]`

### 收斂
1. **主案:新聞數字翻譯機**:A 組合併,加上 B 的「那時你幾歲」。最穩、可以一直更新。
2. ★ **備案:辯論 Bingo**:最不像樣板、最好玩,但 **10/31 之後就沒用了**,而且格子用詞很容易被看成偏袒某陣營。想要「有時效、有話題」就選它,要在 10/30 前上線。
3. **小案:颱風待辦清單**:最實用但最不新穎,政府和媒體都有類似的東西。

### 陷阱(看起來好,其實不要做)
- **颱風停班停課賭盤**:拿災害做下注,觀感差;又要即時預報,靜態網頁做不到
- **「我家會不會淹」問答**:寫死的資料可能讓人誤判安全,有實際傷害風險
- **候選人資產比大小/積木塔**:選舉期間排名比較,容易被說帶風向
- **供應鏈 roguelike**:幾天內做不完,範圍太大

### 刺激問題(如果以上都不想做)
> 如果這個網頁**只能放一個數字**,你會放哪一個?為什麼大家應該在意它?
